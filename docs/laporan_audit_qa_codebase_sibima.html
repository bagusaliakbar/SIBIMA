3. Analisis Mendalam Temuan Kritis (Blocker & Risiko Kehilangan Data)

P0-01

Penghapusan Permanen Nilai Penguji & Riwayat Revisi Saat Admin Mengedit Jadwal (Cascade Delete Data Loss)

app/Services/ScheduleService.php : L39–L55
Akar Masalah (Root Cause)

Pada ScheduleService::updateSchedule() baris 49, sistem memanggil $schedule->details()->delete(); lalu membuat ulang baris SeminarScheduleDetail / ThesisDefenseScheduleDetail dari awal. Padahal tabel seminar_revisions dan thesis_defense_revisions memiliki constraint ->onDelete('cascade') terhadap tabel detail jadwal tersebut.

Skenario Dampak di Produksi

Jika ujian di suatu ruangan telah berlangsung, dosen telah menginput nilai komponen dan catatan revisi, lalu Admin mengedit jadwal tersebut (misalnya hanya memperbaiki typo nama ruangan atau link Zoom), maka seluruh nilai penguji, catatan revisi, riwayat diskusi revisi, dan status ACC revisi untuk seluruh mahasiswa di jadwal tersebut langsung terhapus permanen! Token QR Berita Acara juga ikut berubah.

Kode Saat Ini (Rentan Menghapus Data):
// app/Services/ScheduleService.php (L48-L51)
$schedule->details()->delete();

$this->saveDetails($schedule, $detailModelClass, $data['details'] ?? [], $schedule->date);
Rekomendasi Perbaikan (Upsert / Reconcile tanpa Cascade Delete):
// Rekonsiliasi berdasarkan thesis_id / id detail eksisting:
// 1. Update detail sesi yang thesis_id-nya masih ada di jadwal
// 2. Pertahankan primary key id & verification_token
// 3. Hanya hapus detail yang benar-benar dikeluarkan dari daftar
P0-02

Filter "Mahasiswa Bimbingan Pasif" pada Broadcast WA Tidak Berfungsi (Bug Atribut $lastSession->date)

app/Services/WaBroadcastService.php : L116–L140

Method getMahasiswaBimbinganPasif() mengurutkan dan mem-parsing $lastSession->date, padahal pada model MentoringSession kolom waktu bimbingan bernama scheduled_at. Karena $lastSession->date bernilai null, ekspresi Carbon::parse(null) menghasilkan waktu hari ini (Carbon::now()), sehingga pengecekan ->lt($thresholdDate) selalu menghasilkan false. Akibatnya, mahasiswa yang vakum bimbingan berbulan-bulan tidak pernah terjaring oleh broadcast WA.

Kode Saat Ini:
$lastSession = $thesis->mentoringSessions->sortByDesc('date')->first();
if (!$lastSession) return true;
return Carbon::parse($lastSession->date)->lt($thresholdDate);
Rekomendasi Perbaikan:
$lastSession = $thesis->mentoringSessions->sortByDesc('scheduled_at')->first();
if (!$lastSession || !$lastSession->scheduled_at) return true;
return Carbon::parse($lastSession->scheduled_at)->lt($thresholdDate);
HIGH — P1

4. Analisis Temuan Mayor (Bug Fungsional & Kontradiksi Otorisasi)

P1-01 ExaminerService.php (L71–L82)

Status ACC Revisi ('approved') Tertimpa Saat Simpan/Edit Nilai

storeGrading() mengatur 'status' => ($detail->thesis->pembimbing1_id === $user->id) ? 'approved' : 'completed'. Jika Penguji 1/2 sudah menyetujui revisi mahasiswa (approved), lalu mengedit nilai angka, status revisi mahasiswa ter-reset kembali menjadi completed (Menunggu Revisi).

P1-02 Seminar/DefenseScheduleController (L421)

Kontradiksi 403 Forbidden Cetak PDF Jadwal oleh Mahasiswa

Middleware controller mengizinkan role:admin,kaprodi,dosen,mahasiswa untuk exportPdf, tetapi di baris 421 terdapat pengecekan if (!in_array($user->role, ['admin', 'kaprodi', 'dosen'])) abort(403); yang langsung menolak mahasiswa.

P1-03 GraduationController.php (L107–L160)

Bypass Validasi Eligibilitas Sidang pada POST Yudisium Mahasiswa

Pengecekan $isEligible = $hasDefense && $isDefensePassed hanya ada di studentIndex() (tampilan form), namun tidak diperiksa di studentStore() (POST /student/graduation). Mahasiswa yang belum lulus sidang dapat mengirim request POST langsung.

DownloadController & Scheduler

Mismatch Folder Berkas Admin (403) & Duplikasi Cron Pengingat

P1-04: adminRegister() menyimpan berkas ke seminar_applications/ sedangkan DownloadController hanya mengizinkan SeminarApplication_files/.
P1-05: Cron app:send-schedule-reminders didaftarkan di bootstrap/app.php (08:00) sekaligus routes/console.php (07:00), memicu pengiriman WA ganda.
